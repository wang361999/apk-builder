## 系统架构概览

产品授权系统采用 **官网集中管理 + 项目端验证** 的架构，分为两端：

```
┌─────────────────────────────────────────────────────────────────┐
│                        官网（本项目）                              │
│  ┌───────────────┐   ┌───────────────┐   ┌───────────────┐       │
│  │  产品管理后台  │   │  订单管理系统  │   │  授权码管理系统 │       │
│  │ (创建产品/版本) │   │ (用户下单/支付) │   │ (生成/绑定/校验)│       │
│  └───────┬───────┘   └───────┬───────┘   └───────┬───────┘       │
│          │                   │                   │               │
│          └───────────────────┼───────────────────┘               │
│                              ▼                                   │
│                    ┌───────────────────┐                        │
│                    │  API 服务 (Next.js) │                        │
│                    │ /api/license/verify │                        │
│                    │ /api/products/:slug│                        │
│                    └─────────┬─────────┘                        │
└──────────────────────────────┼──────────────────────────────────┘
                               │ HTTPS
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│                     用户项目端（集成 SDK）                        │
│  ┌─────────────────────────────────────────────────┐            │
│  │  license-verifier.ts / .js                      │            │
│  │  - initLicense()      启动时验证授权             │            │
│  │  - startPeriodicCheck()  定时校验（24h）         │            │
│  │  - checkVersion()     检查版本更新               │            │
│  │  - licenseMiddleware() Express 中间件           │            │
│  └─────────────────────────────────────────────────┘            │
└─────────────────────────────────────────────────────────────────┘
```

### 核心概念

| 概念 | 说明 |
| --- | --- |
| **官网** | 部署本项目的站点，负责管理产品、版本、订单、授权码，并提供验证 API |
| **产品（Product）** | 可销售的项目，拥有唯一标识 `slug`，可配置多个版本与套餐 |
| **版本（Version）** | 产品的某个发布版本，包含源码包、更新日志、下载地址 |
| **授权码（License Key）** | 用户购买后获得，格式 `ET-XXXXXXXX-XXXXXXXX-XXXXXXXX`，用于项目端验证 |
| **域名绑定** | 授权码绑定运行域名，防止授权码被滥用到多个站点 |
| **SDK** | 嵌入用户项目的验证模块，负责与官网 API 通信完成验证 |

### 数据流向

1. 管理员在官网后台创建产品与版本
2. 用户在官网购买产品，系统生成授权码
3. 用户绑定运行域名并下载源码
4. 用户将 SDK 集成到项目并部署
5. 项目启动时 SDK 调用官网 API 验证授权码与域名
6. 验证通过则正常运行，失败则触发未授权处理

## 后台配置流程

管理员登录后台（`/admin`）后，按以下流程完成产品配置。

### 第一步：创建产品

进入 **产品销售 → 产品管理**，点击"创建产品"：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 产品名称 | 展示给用户的名称 | ET 博客系统 |
| 产品标识（slug） | 唯一标识，用于 API 调用，全小写英文 | `et-blog` |
| 产品描述 | 详细介绍 | 基于 Next.js 的现代化博客系统 |
| 授权类型 | 永久授权 / 订阅授权 / 按域名授权 | 按域名授权 |
| 最大域名数 | 一个授权码可绑定的域名数量 | 3 |
| 有效期 | 授权有效期（永久授权则忽略） | 365 天 |
| 产品价格 | 展示价格 | ¥199 |
| 状态 | 上架 / 下架 | 上架 |

创建后系统会生成 `product_id`，用户前台即可看到该产品。

### 第二步：设置版本

进入产品详情页，点击"新建版本"：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 版本号 | 语义化版本号 | `1.0.0` |
| 版本标题 | 简短描述 | 首个正式版本 |
| 更新日志 | 详细变更说明 | 新增文章管理、评论系统... |
| 源码包 | 上传 zip 压缩包 | `et-blog-1.0.0.zip` |
| 文件大小 | 自动计算或手动填写 | 12.5 MB |
| 下载密码 | 可选，保护源码包 | `et2024` |
| 是否最新版本 | 标记 `isLatest`，同一产品仅一个 | 是 |

> 注意：每个产品同一时间只能有一个"最新版本"。发布新版本时，旧版本会自动取消最新标记。

### 第三步：管理订单

进入 **产品销售 → 订单管理**，可以查看所有用户订单：

- 查看订单状态（待支付 / 已支付 / 已发货 / 已完成 / 已退款）
- 查看关联的授权码
- 手动创建订单（线下支付场景）
- 处理退款申请

### 第四步：授权码管理

进入 **系统设置 → 授权管理**，可以：

- 查看所有授权码及其状态
- 手动生成授权码（赠送给用户）
- 启用 / 禁用授权码
- 查看授权码绑定的域名
- 查看验证日志

## 用户购买流程

用户在前台的完整购买与使用流程：

### 1. 浏览产品

用户访问官网前台 `/products` 页面，浏览所有上架产品，查看产品介绍、功能特性、价格等信息。

### 2. 选择套餐

在产品详情页选择授权套餐：

- 永久授权：一次购买永久使用
- 订阅授权：按年/月付费
- 按域名授权：根据绑定域名数量计费

### 3. 下单

点击"立即购买"生成订单，订单包含：

- 订单号
- 产品信息
- 套餐与价格
- 收货邮箱（用于接收授权码）

### 4. 支付

支持以下支付方式：

- 支付宝 / 微信支付（在线支付）
- 银行转账（线下，需管理员确认）
- 人工核销（管理员手动标记已支付）

### 5. 获取授权码

支付成功后，系统自动生成授权码并通过以下渠道发送：

- 邮件发送到收货邮箱
- 显示在"我的订单"页面
- 可在 **个人中心 → 我的授权** 查看

授权码格式：`ET-XXXXXXXX-XXXXXXXX-XXXXXXXX`

### 6. 绑定域名

用户在 **个人中心 → 我的授权** 页面绑定运行域名：

1. 输入将要部署的域名（如 `app.my-domain.com`）
2. 点击"绑定域名"
3. 系统校验域名数量是否超限
4. 绑定成功后，该授权码只能在此域名下使用

> 提示：本地开发可绑定 `localhost` 用于测试。每个授权码可绑定域名数取决于套餐配置。

### 7. 下载源码

绑定域名后，可下载源码：

1. 在"我的授权"页面点击"下载源码"
2. 如版本设置了下载密码，需输入密码
3. 下载得到 zip 压缩包
4. 解压后即可开始项目集成

## 项目端集成

用户拿到源码与授权码后，将 SDK 集成到项目中。

### 1. SDK 安装

将 SDK 文件复制到项目中：

```bash
# TypeScript / Next.js 项目
cp license-verifier.ts your-project/lib/license-verifier.ts

# Node.js / CommonJS 项目
cp license-verifier.js your-project/lib/license-verifier.js
```

环境要求：Node.js 18+（内置 fetch），无需安装额外依赖。

### 2. 配置环境变量

在项目根目录创建 `.env` 文件：

```bash
# 授权码（在官网购买后获得）
LICENSE_KEY=ET-XXXXXXXX-XXXXXXXX-XXXXXXXX

# 官网授权验证接口地址
LICENSE_VERIFY_URL=https://your-domain.com/api/license/verify

# 运行域名（可选，不填则自动识别）
LICENSE_DOMAIN=app.my-domain.com
```

### 3. 初始化授权验证

在项目入口文件调用 `initLicense`：

**TypeScript / Next.js：**

```typescript
// app/instrumentation.ts 或 项目入口
import { initLicense } from './lib/license-verifier';

export async function register() {
  await initLicense({
    licenseKey: process.env.LICENSE_KEY!,
    verifyUrl: process.env.LICENSE_VERIFY_URL!,
    onUnauthorized: (result) => {
      console.error('授权失效：', result.message);
      // 发送告警邮件、记录日志、关闭服务等
    },
    startPeriodic: true, // 启动 24 小时定时校验
  });
}
```

**Node.js / Express：**

```javascript
const { initLicense } = require('./lib/license-verifier');

await initLicense({
  licenseKey: process.env.LICENSE_KEY,
  verifyUrl: process.env.LICENSE_VERIFY_URL,
  onUnauthorized: (result) => {
    console.error('授权失效：', result.message);
  },
});
```

### 4. 验证授权

SDK 提供多种验证方式：

**路由中间件保护（Express）：**

```javascript
const { licenseMiddleware } = require('./lib/license-verifier');
app.use('/api', licenseMiddleware);
```

**Next.js Edge Middleware：**

```typescript
// middleware.ts
import { checkLicenseForMiddleware } from './lib/license-verifier';

export async function middleware(request) {
  return await checkLicenseForMiddleware(request, {
    licenseKey: process.env.LICENSE_KEY!,
    verifyUrl: process.env.LICENSE_VERIFY_URL!,
    unauthorizedUrl: '/unauthorized',
  });
}
```

**手动获取授权状态：**

```typescript
import { getLicenseStatus } from './lib/license-verifier';

const status = getLicenseStatus();
// { isVerified: true, licenseInfo: {...}, lastCheckTime: 1700000000000 }
```

更详细的使用说明请参考 [sdk/README.md](../sdk/README.md)。

## 版本更新流程

当管理员发布新版本后，已部署项目的 SDK 可以自动检测并提示用户更新。

### 1. 发布新版本

管理员在后台发布新版本：

1. 进入 **产品管理 → 产品详情**
2. 点击"新建版本"
3. 填写版本号（如 `1.1.0`）、更新日志
4. 上传新版本源码包
5. 标记为最新版本（系统自动取消旧版本的最新标记）
6. 发布

### 2. SDK 自动检测

用户项目中集成的 SDK 通过 `checkVersion` 或 `startVersionCheck` 自动检测更新：

```typescript
import { startVersionCheck } from './lib/license-verifier';

// 每小时检查一次版本更新
startVersionCheck(
  'https://your-domain.com/api',  // 官网 API 地址
  'et-blog',                       // 产品 slug
  '1.0.0',                         // 当前版本
  (result) => {
    if (result.hasUpdate) {
      console.log(`发现新版本 ${result.latestVersion.version}`);
      console.log(`更新日志：${result.latestVersion.changelog}`);
      // 通知用户更新：发邮件、写日志、更新 UI 提示
    }
  }
);
```

### 3. 提示用户更新

检测到新版本后，可通过以下方式提示用户：

- 在管理后台显示更新通知横幅
- 发送邮件通知
- 记录到日志供运维查看
- 在 API 响应头中加入版本提示

### 4. 用户更新流程

用户收到更新提示后：

1. 登录官网，进入"我的授权"
2. 下载最新版本源码包
3. 按更新日志升级项目代码
4. 修改项目中的当前版本号（用于后续版本检查）
5. 重新部署项目
6. SDK 重新检测，确认已是最新版本

### 版本检查缓存说明

- `checkVersion` 每次调用都会请求 API，建议配合自身缓存策略使用
- `startVersionCheck` 默认每小时检查一次，可通过 `clearInterval(timer)` 停止
- 版本检查失败（网络错误等）不会影响授权验证功能，两者相互独立

## API 接口文档

### 1. 授权验证接口

验证授权码是否有效，并校验域名是否已绑定。

**请求**

```
POST /api/license/verify
Content-Type: application/json
```

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `license_key` | string | 是 | 授权码 |
| `domain` | string | 是 | 运行域名 |

**请求示例**

```bash
curl -X POST https://your-domain.com/api/license/verify \
  -H "Content-Type: application/json" \
  -d '{"license_key":"ET-XXXXXXXX-XXXXXXXX-XXXXXXXX","domain":"app.my-domain.com"}'
```

**成功响应（授权有效）**

```json
{
  "valid": true,
  "code": "valid",
  "message": "授权验证通过",
  "project_name": "ET 博客系统",
  "project_type": "blog",
  "expires_at": "2025-12-31T23:59:59Z",
  "max_domains": 3,
  "bound_domains": 1
}
```

**失败响应（授权无效）**

```json
{
  "valid": false,
  "code": "domain_mismatch",
  "message": "域名未绑定到该授权码",
  "max_domains": 3,
  "bound_domains": 1
}
```

**状态码说明**

| code | 说明 |
| --- | --- |
| `valid` | 授权有效 |
| `no_license` | 未提供授权码 |
| `no_verify_url` | 未配置验证接口地址 |
| `network_error` | 网络请求失败 |
| `unauthorized` | 授权码无效或已禁用 |
| `domain_mismatch` | 域名未绑定 |
| `expired` | 授权已过期 |
| `max_domains_exceeded` | 已达最大域名绑定数 |

### 2. 版本检查接口

获取产品的版本信息，用于检测更新。

**请求**

```
GET /api/products/:slug
```

**路径参数**

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `slug` | string | 产品标识 |

**请求示例**

```bash
curl https://your-domain.com/api/products/et-blog
```

**响应示例**

```json
{
  "id": 1,
  "name": "ET 博客系统",
  "slug": "et-blog",
  "description": "基于 Next.js 的现代化博客系统",
  "versions": [
    {
      "id": 10,
      "version": "1.1.0",
      "title": "新增评论系统",
      "changelog": "- 新增评论功能\n- 优化 SEO\n- 修复若干 Bug",
      "downloadUrl": "https://your-domain.com/api/products/et-blog/versions/10/download",
      "downloadPassword": "et2024",
      "fileSize": "13.2 MB",
      "isLatest": true,
      "createdAt": "2024-06-15T10:00:00Z"
    },
    {
      "id": 9,
      "version": "1.0.0",
      "title": "首个正式版本",
      "changelog": "- 初始版本发布",
      "downloadUrl": "https://your-domain.com/api/products/et-blog/versions/9/download",
      "downloadPassword": null,
      "fileSize": "12.5 MB",
      "isLatest": false,
      "createdAt": "2024-01-01T10:00:00Z"
    }
  ]
}
```

**字段说明**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `versions` | array | 版本列表，按时间倒序 |
| `versions[].version` | string | 版本号 |
| `versions[].title` | string | 版本标题 |
| `versions[].changelog` | string | 更新日志（支持换行） |
| `versions[].downloadUrl` | string | 源码下载地址 |
| `versions[].downloadPassword` | string \| null | 下载密码（无则为 null） |
| `versions[].fileSize` | string | 文件大小 |
| `versions[].isLatest` | boolean | 是否为最新版本 |
| `versions[].createdAt` | string | 发布时间（ISO 8601） |

SDK 的 `checkVersion` 函数会自动解析此响应，找到 `isLatest` 为 `true` 的版本进行对比。

## 常见问题

### Q1: 授权验证失败，提示 "域名未绑定"

用户需要先在官网个人中心绑定运行域名，确保绑定的域名与项目实际运行域名完全一致（注意 `www.` 前缀）。本地开发可绑定 `localhost`。

### Q2: 用户更换域名后如何处理？

1. 用户在官网个人中心解绑旧域名
2. 绑定新域名
3. 项目中更新 `LICENSE_DOMAIN` 环境变量
4. 重启项目，SDK 重新验证

### Q3: 授权码被多人使用怎么办？

授权码与域名绑定，绑定域名数量受 `max_domains` 限制。超出限制将无法绑定新域名。如发现盗用，管理员可在后台禁用授权码。

### Q4: 官网服务宕机，用户项目还能运行吗？

JS 版本 SDK 支持离线宽限：网络错误时读取本地缓存（`.license-cache.json`），48 小时内仍判定为已授权。建议官网保持高可用部署（Vercel 自动支持）。

### Q5: 如何迁移官网到新域名？

1. 在新 Vercel 项目部署官网
2. 更新 DNS 解析指向新域名
3. 通知所有用户更新 `LICENSE_VERIFY_URL` 与版本检查 API 地址
4. 旧域名保留一段时间做过渡

### Q6: 版本检查 API 返回 404

确认产品 `slug` 正确，且该产品已创建至少一个版本。检查 API 地址是否为根地址（如 `https://domain.com/api`，不要带 `/products`）。

### Q7: 用户购买后多久能收到授权码？

在线支付成功后立即生成并发送邮件，通常 1 分钟内可收到。线下支付需管理员手动确认后生成。

### Q8: 如何批量导入授权码？

管理员可在后台 **系统设置 → 授权管理** 批量生成授权码，或通过 API 接口批量创建，适用于渠道分发场景。

### Q9: 授权码可以退款吗？

可以。管理员在订单管理中处理退款，退款后授权码自动禁用。已部署的项目在下次定时校验时会检测到授权失效。

### Q10: SDK 升级会影响现有授权吗？

不会。SDK 升级仅替换验证逻辑文件，授权码与域名绑定关系存储在官网数据库中，与 SDK 版本无关。建议保持 SDK 为最新版本以获得更好的稳定性与功能。
